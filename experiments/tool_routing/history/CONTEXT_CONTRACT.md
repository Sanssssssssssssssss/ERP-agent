# 能力选择上下文 v12（实验候选）

当前入口：`selection_batch` 共用真实上下文与工具目录；GPU worker 一次 thinking，再逐组读取 A/B 分数。默认关闭；仅 `ERP_OPENJEV_CONFIG` 显式启用。缺少工具时用 `recover_capabilities` 补发，审批和未知写入保护仍由原执行链负责。

v11 移除选择阶段额外注入的验收指令，保留用户目标和目标状态；账本说明明确 approved 仍待执行。runtime 必须保留的组在选择前传入，相关性评分与最终工具合并分别记录。全池入口：`python -m experiments.tool_routing.openjev_regression`。旧正标签表示“有支持的可用能力”，不能全部解释为业务必需；原标签成绩与实际必需能力分析分别保留。以下为各历史轮次记录。

v12 去掉固定证据免责声明 `historical_action_only`，避免误认为是其他运行的动作；实际状态、来源与新鲜度保留。账本只记录已尝试操作，不能代替全部业务待办；创建成功不等于已确认。2003 的真实退步已登记回归，v11 未晋级。

唯一组装入口：`erp_harness.app.routing_context.assemble_context`。在线传当前request与宿主goal/stage/identity/ledger/World；历史回放传冻结request与同一时点的state。模型消息统一由`selection_messages`生成，候选定义读取真实工具目录。

|输入|规则|
|---|---|
|当前目标|保留宿主目标、requested_outcome与scope_known；不额外注入执行器验收指令；未知范围不补猜|
|动作账本|保留approved/rejected/unknown和未决动作；采集情况单独放input_coverage，不表示业务完成；聊天及工具日志不能授予审批|
|业务观察|保留来源ID、前缀消息位置及新鲜度；同记录明确后续验证过的字段，其旧值退出工作视图，原始日志与来源引用保留；日志不能证明当前数据库状态|
|错误与状态|最新工具批次保留完整错误；已被账本覆盖的审批错误转为历史引用；较早未关联失败保留原先有界的错误摘要与unknown历史引用，不宣称仍阻塞或已经解决|
|输入覆盖|大小限制、字段遗漏明确命名；不使用可能被理解成财务预算的fact_budget|
|工具面|列实际基础工具、runtime保留组；候选组包含真实工具名及原生目录中的用途说明；HIDE仍可使用基础工具|

静态安全规则只放system。EXPOSE/HIDE明确指下一轮执行模型是否获得该组工具，与界面展示、向人询问及自主执行无关。仅移除已知固定的非授权声明；真实ACL拒绝、审批与未知状态保留。来源重复、跨模型或跨实例时，不推断覆盖关系；World合并视图也不按旧回执日期判断字段先后。输入对照保留相同解码；另用`q4_decision_readout`固定思考，验证末位只允许两个声明选项的输出契约，单独计分。

执行：离线检查→四个真实错点×两种顺序→两个原正确节点×两种顺序。每版12次本地GPU生成，原标签不改，不执行Odoo。v1仍纠结旧字段；v2移出旧字段后暴露旧审批错误误读；v3分离当前与历史事件；v4只补真实工具用途，system不变；v5只补工具可调用性的定义。冻结请求、组装器哈希和判定规则；分别报告错点与保护对照。分类正确计为正确；理由冲突仅作诊断记录。

v6只将选项绑定当前能力组；v7只改system为未完成需求与候选工具匹配；v8只补共享阶段判据和未解决历史失败原因。分别留存，不因一组分数上升就晋级。`prepare-extra`冻结8个额外历史案例/能力组合（16次）；`prepare-recovery`仅重放其中有真实输入缺口的附件与诊断（4次）。`q4_prompt_metrics`分别统计漏选、多选、未知、顺序分歧及阈值扫描；正标签表示可用性，可能存在合法基础工具替代，不等同唯一正确业务路径。A/B读分未校准为正确概率。

复现：用项目Python运行`-m experiments.tool_routing.q4_standard_context prepare <新输出目录>`；用已隔离的CUDA Python运行同模块的`run <同目录>`，stderr写入该目录`probe-error.log`。输入由宿主侧真实代码生成；GPU进程只读取冻结消息，不另组装一套。

旧训练模型仍使用其已绑定的host_facts_v1；新契约未验证前不替换生产worker。后续接入必须复用本入口、登记契约版本与源码哈希，不能在worker里另写一份投射。此轮不改审批/执行器、不重新训练。

v9补实际基础工具的用途、候选工具完整参数schema；验证回包保留delivery与record_model，并按明确的record_model读取invoice_records，避免把发票结果挂在向导模型上。只投射已有证据，不生成SMTP成功或任务完成结论。system明确允许有依据的可选检查，开放工具不代表必须调用。

`prepare-all`固定14个历史节点/能力组合，共28次判断，原标签不变。运行结果及接入门槛见[接入验证](Q4_INTEGRATION_RESULTS.md)。GPU worker草案保存在本机隔离目录；门槛未过时不增加生产入口。
