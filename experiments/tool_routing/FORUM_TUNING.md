历史下一步只是覆盖代理，不是唯一正确路径。独立审阅允许多种合理集合：候选 9/9 含无关能力；例如发票回读时仍选择员工、休假、跨实例。交换选项顺序，69 个 dev 节点只有 12 个保持同一能力集合。224 个测试节点中，160 个非空参考的覆盖为未训练 147/160、训练后 144/160；不能称业务通过率。候选 SDK P50/P95 约 812/1,182 ms，不含工具发布和主模型。

补充上轮计划另取 8 个 dev 节点、原始/训练模型各一次，再补同格式空计划对照，共 32 次。成对输入只差过去的计划内容，原请求之后的响应不进入输入。训练版覆盖由 5/6 到 6/6，平均选择由 4.50 到 6.75 组。说明计划内容会影响选择，也增加误选负担；样本太少，不能据此晋级。最初直接与紧凑 JSON 比较混入了格式变化，该比较不用于内容归因。

修正并保留的实验问题：

- SDK 的概率保留四位小数；`.5000` 可能与实际 `choice` 不同。改用真实 `choice`，离线断言覆盖此问题，复用 431 个已记录基线响应。
- 小显存微批常只有 1–2 条。补梯度累积后训练损失下降，但 dev 最优仍低于未训练具体选项。累积目标 16，微批边界允许 16–19 条、尾批可不足；共 417 次更新。没有证明训练批量是原来失败的唯一原因。
- 两次中断实验原样保留：第一次修正概率解码，第二次修正训练批量。完整运行选中第 1 轮；训练损失改善不等于路由改善。

剩余确定缺口：历史工具调用包含绕路；训练正例中跨实例、迁移各 1 条，附件 1 条，员工/请假 0 条。摘要也不等于完整业务状态。后续应先审训练用历史节点的能力必要性、补真实稀有组，再测新业务家族。当前数据不支持判断 Laya 的能力上限，也不支持省掉主模型编排轮。
