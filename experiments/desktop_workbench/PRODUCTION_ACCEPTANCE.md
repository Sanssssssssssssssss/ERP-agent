# 桌面业务工作区 0.3 验收

起点：`64d8c81`。日期：2026-09-09。原型保留在 `prototype/`，本轮修改正式 React/Electron 工作台。

本轮目标：让用户在真实业务运行中看清目标、当前动作、Odoo 事实、审批边界和具体回执。
实现由 Luna 分块完成，主代理审查、集成并进行原生桌面验收。

## 验收范围

| 用户可见行为 | 检查与证据 |
| --- | --- |
| 会话、多业务和四个子页 | 会话恢复、业务切换、迟到响应隔离；1280×800 与 1600×1000 |
| 执行台 | 紧凑目标、完整指令可展开、当前阶段与浏览阶段区分；基础核验范围明确 |
| 单据与文件 | 真实记录预览、观察时间、来源回执；原生导出路径、Odoo 记录入口 |
| 变更与审批 | 拟修改值与前态、逐项批准/拒绝；批准不等于执行完成 |
| 运行详情 | 运行、轮次、工具、输入输出、用量与耗时；进行中的工具可见 |
| 证据定位 | 跨页定位到正确运行和工具；历史浏览不改变当前执行状态 |
| 不确定写入 | 不自动重发；明确只读核对；证据不足仍保留不确定状态 |
| 状态语义 | 历史记录不证明新运行完成；订单草稿不能通过销售完成检查 |
| 桌面边界 | 主进程校验业务作用域；只打开已观察记录；导出由保存对话框选择路径 |
| 真实案例 | 冻结 Nimbus 销售开票自然结束；页面与独立 10 条业务规则核对 |

## 实现说明

正式页面复用已安装的 Radix Themes 和 Lucide。单据入口由主进程核对当前业务的
已观察记录，采用 Odoo 19 保留兼容的记录路由；参见
[Odoo 19 router 源码](https://github.com/odoo/odoo/blob/19.0/addons/web/static/src/core/browser/router.js)。
业务回执导出包含当前事实及选定运行的 Trace，原生保存对话框指定目标文件，临时文件写入成功后替换目标。
核对不确定写入复用 native action verifier，仅读取 Odoo 和更新本地账本，不调用模型或再次发送写操作。

## 审查中修复的问题

| 问题 | 修复与核验 |
| --- | --- |
| 不存在的开票向导仍生成审批 | 在 native action 预检确认全部目标、向导关联和订单确实存在；审批后删除目标也拒绝写入 |
| 历史缓存可能把新运行显示为通过 | 检查当前运行、观察时间和规定检查项；过期或证据不足显示未知 |
| 订单读取省略 invoice_ids 导致误报未知 | 当前运行必须实际读取同一订单及发票；新鲜独立回读可补充该订单的精确关联 |
| 创建向导被显示成未知阶段 | 按结构化模型及操作归属开票阶段，创建成功仍不代表过账核验通过 |
| SO 和发票具有相同数字 ID 时选错 | 单据选择使用 model:id；原始读取回执保留准确运行、工具和时间 |
| 审批参数难看清、待办淹没在历史里 | 参数与前态按列展示；创建的空前态明确标记；待审批与不确定动作优先 |
| 回执定位停在预检而不是执行 | 同 action_id 定位最后执行回执；独立回读指向当前快照作用域 |
| 手动切换运行保留了旧动作定位 | 选择运行清空跨页目标，返回该运行总览；从动作点击运行节点也正确显示总览 |
| 页面过高、状态不透明 | 收拢长指令和辅助会话；阶段、当前动作、Odoo 事实前置，四个正式子页各自承载内容 |
| 真实记录较多时选择底部发票，把右侧详情滚出视野 | 单据列表独立滚动；1280×800 下选择末尾记录仍可同时看到其预览 |

## 回归与压力检查

- 原生相关 Python 回归：**135 项通过**。历史 `test_baseline_fixes`、`test_native_reads` 依赖 MCP SDK，未在无 MCP 的原生包中运行。
- TypeScript 类型检查、前端构建、桌面主进程 self-check、renderer-check 通过。
- 50 次会话切换约 491 ms，50 次业务切换约 10 ms，20 次顺序业务切换约 830 ms。
  300 条 Trace 事件约 314 ms，合并为各 1 次 Trace/业务刷新；重复创建、发送、开始、审批、取消各只提交 1 次。
- 上述压力数值来自本机确定性 bridge 回归，衡量界面去重与响应，不代表 Odoo 或模型并发容量。
- 回归覆盖未知写入不重发、只读核对、旧响应隔离、历史浏览、作用域校验、准确回执定位及原生导出边界。
- Windows 测试临时 SQLite 目录仍有清理时文件占用提示，断言均通过；未发生对应的真实桌面崩溃。

## 交付边界

V1 主机同时执行一项任务，业务页目前面向销售开票。付款、出库、采购等只展示实际观察事实，未扩展为独立业务工作台。
原生 Windows 包尚未签名。多人权限运营、长期运行、多客户隔离及更大业务样本尚未完成验收。
金额、付款条件、副作用等冻结场景规则由独立案例核验器检查；界面基础 7 项核验不覆盖全部业务正确性。

原始证据保留在 `.runtime/workbench-production-20260909/`：两次 trace、首次 7/10 与最终 10/10 核验、
冻结基线、原生导出及真实页面截图。它们不进入源码仓库；提交仅包含代码、测试与脱敏验收说明。
