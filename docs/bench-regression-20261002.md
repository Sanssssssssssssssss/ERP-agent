## 宿主契约与适用范围

新增 `read_purchase_allocation` 只读能力；同一份检查用于模型查询和宿主保护。它沿当前身份、字段 ACL、公司、产品和单位回读数量，检查每单来源容量和多单共同分配。结束时直接从动作账本定位采购，必要时按精确来源名字查回既存销售单。未确认写入保持未知，不重放。多实例混合、单位/BOM转换、缺少证据也返回未知。

按销售需求采购时，宿主在已有 task-evidence 文件中明确绑定如下范围；示例 ID 只是配置结构示意，不是新付费案例：

```json
{
  "purchase_sources": [{
    "product": {"model": "product.product", "domain": [["id", "=", 2]]},
    "source": {"model": "sale.order", "domain": [["id", "in", [2, 4]]], "field": "name"},
    "purchases": {"model": "purchase.order", "domain": [["id", "in", [8, 9]]]},
    "check_demand_capacity": true,
    "minimum_per_origin": 1
  }]
}
```

完整 specification 仍须包含原有版本、指令哈希和身份绑定。`purchases` 应包含本业务所有竞争采购单；未提供时只检查当前动作目标和结束账本中的目标。最小正分配量取决于宿主已确认的单位规则，默认为 `1e-6`；整数成品案例使用1。检查按所绑定产品进行，不能用另一个模型的同号 ID 充当销售来源。

**当前四题原配置没有这个强制宿主契约**。未绑定时，结束检查保存关联诊断，普通补库存的余量政策仍需确认，不会擅自当成业务失败。来源可行分配也不等于实际预留或写入授权。这是当前实际生效范围，不能宣称所有业务均已强制覆盖。

每次检查最多20张采购、20张销售、每类500条明细；更大范围、BOM展开或不同单位需另行绑定完整证据，当前保持未知。多次新鲜 RPC 也不构成数据库事务快照。
