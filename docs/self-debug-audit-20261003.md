# 工具故障与 self debug 覆盖 · 2026-10-03

**44 个原生工具中，31 个在本次检查的异常分支缺少结构化原因；其余 13 个直接回包有分类，但进入 self debug 后分类丢失。**这是故障契约检查结果，不能当作真实业务故障率。

| 根因位置 | 工具数 | 当前缺口 |
|---|---:|---|
| `NativeCapabilities.call` 共用异常入口 | 24 | 业务能力、诊断和异步工具只返回错误正文，缺少稳定原因与下一步 |
| 原生动作的通用异常回包 | 5 | 部分异常只剩文本；已有授权交接、方法拒绝、不确定写入处理仍需按各自分支判断 |
| 员工、假期查询响应模型 | 2 | `SearchEmployeeResponse`、`SearchHolidaysResponse` 序列化过滤了读取入口已生成的分类和下一步 |
| 其余读取工具 → `summarize_run` | 13 | 直接回包能区分连接、权限、查询等；汇总退化为 `tool_failed / unknown / fresh_read_or_validate` |

问题既发生在工具回包，也发生在响应序列化和诊断汇总。此前增加的结构化未知字段恢复只覆盖字段发现分支，不能替代其他故障分类。写入的超时尤其需要结合发送阶段和动作账本判断，不能套用读取重试建议。

## 实际轨迹

核对既有[冻结案例](../experiments/agent_regression/bench_recovery_cases.json)的源哈希，四道业务共有 **41 个工具失败节点，涉及 7 种工具**：

| 工具 | 失败节点 |
|---|---:|
| 读取记录 | 17 |
| 查找记录 | 10 |
| 读取业务 SOP | 8 |
| 读取已存证据 | 3 |
| 执行业务方法 | 1 |
| 查询字段定义 | 1 |
| 当前运行诊断 | 1 |

其中 30 个原回包有原因标签，26 个有下一步。把未改动的原回包逐个送入当前诊断汇总，在显式 fixture 范围内重放分类，41 个均归为通用 `tool_failed`。这是离线分类重放，原模型实际只调用过一次运行诊断，当时返回 `identity_or_scope_unavailable`。不能把 41 个重放节点称为 41 次模型 self debug 失败，也不能据此重判原业务结果。

旧回包早于本轮及此前字段修复；缺少结构化恢复参数时仍走通用汇总。字段拒绝后的真实模型行为见[此前审计](field-self-debug-20261003.md)：7 个节点随后成功重读原目标、1 个查询现场字段定义、9 个未见显式目标闭环。

辅助工具还发现 6 个来源有回包或汇总缺口：`get_odoo_sop`、`read_observation`、`search_observations`、`configure_odoo_tools`、`recover_capabilities`、`diagnose_current_run`。它们采用源码及历史节点检查，未纳入下述完整注入矩阵；聊天工具的异常分支也尚未全面注入验证。

## 回归与修复顺序

新增[离线入口](../experiments/agent_regression/self_debug_audit.py)及[普通测试](../tests/test_self_debug_audit.py)，覆盖全部 44 个原生工具与 16 类故障，共 **704 个工具／故障组合**：超时、拒绝连接、网络、DNS、TLS、认证、权限、字段 ACL、限流、端点、数据库、服务端、查询、记录缺失、无效回包、回包过大。

使用真实参数验证和共用异常入口，在业务函数执行前注入异常；不调用 Odoo 或模型。矩阵衡量回包保留能力，某些注入类型对本地工具不代表常见真实故障。旧字段、无效工具参数、授权和不确定写入继续由既有局部测试保护。

[基线](../experiments/agent_regression/self-debug-audit-20261003/baseline.json)明确记录开放缺口。测试保护已有分类、发现新增未分类工具；这些已知缺口当前获准存在，所以测试通过不代表它们已修好。修复一个工具后需删除它对应的豁免，防止退回通用文本。

后续修复应按共用入口推进：先补能力异常分类与人事响应字段保留，再让诊断汇总保留可信原因和下一步，最后逐项检查动作的发送阶段与不确定结果。实际故障继续绑定原冻结节点、离线入口和已有局部 API 入口；合成故障只留在离线测试。模型是否依据新提示纠错、最终业务是否通过，需要分别验证。
